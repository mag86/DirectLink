# DirectLink — P2P Desktop Chat Prototype

## Описание

DirectLink — прототип децентрализованного P2P-мессенджера для прямой коммуникации между двумя пользователями без серверов. На этапе прототипа поддерживается текстовый чат с ручным обменом параметрами подключения.

---

## Быстрый старт

### 1. Установка зависимостей

Выполните в терминале:

```bash
npm install
```

### 2. Запуск в режиме разработки

Vite (React) и Electron запустятся вместе:

```bash
npm run dev
```

- После компиляции откроется основное окно DirectLink с чат-интерфейсом.

### 3. Сборка для дистрибутива

Для финальной сборки приложения под все ОС:

```bash
npm run build
```

## Как работает P2P-чат (UI и логика)

### Роли и запуск соединения

- **Чекбокс «Я инициатор соединения»**  
  - Включён — это сторона A (инициатор), она первой создаёт `offer` (signal) для WebRTC.  
  - Выключен — сторона B (приёмник), она ожидает сигнал от инициатора и отвечает.

- **Кнопка «Старт»**  
  - Создаёт новый `Peer` (simple-peer), генерирует новую пару крипто-ключей (Curve25519) и запускает процесс установления WebRTC-соединения.  
  - После нажатия начинает формироваться ваш `SIGNAL` — JSON с SDP-описанием (`signal`) и вашим публичным ключом (`pubkey`).

### Ключи и шифрование

- **Блок «Ваш public key (E2EE)**»  
  - Показывает ваш публичный ключ (base64), приватный ключ хранится только на устройстве.  
  - Публичный ключ автоматически включается в `SIGNAL` и в каждое отправляемое сообщение.  
  - Для шифрования используется `tweetnacl.box` (Curve25519 + nonce):  
    - сообщение шифруется на публичный ключ получателя,  
    - расшифровывается только на его приватный ключ.

### Обмен сигналами (установление P2P)

- **Секция «Ваш SIGNAL»**  
  - Текстовое поле только для чтения с JSON вида:
    ```json
    { "signal": { ... }, "pubkey": "..." }
    ```
  - Кнопка **«Показать QR»** кодирует этот JSON в QR-код (через `react-qr-code`), чтобы второе устройство могло его быстро считать.

- **Секция «Вставьте remote SIGNAL»**  
  - Сюда вставляется чужой `SIGNAL` (JSON) — либо вручную, либо после считывания QR.  
  - Кнопка **«Подключить»**:
    - парсит JSON, сохраняет удалённый `pubkey` для последующего шифрования,  
    - передаёт `signal` в `peer.signal(...)`, что завершает WebRTC-handshake.

### Сообщения и статус

- **Поле сообщений**  
  - Отображает историю:
    - `[Me] ...` — локально отправленные сообщения,  
    - `[Remote] ...` — успешно расшифрованные входящие сообщения,  
    - `[decrypt error]` — если расшифровать не удалось (например, неверный ключ).

- **Поле ввода + кнопка «Отправить»**  
  - Заблокированы, пока P2P-соединение не установлено (`connected === false`).  
  - После успешного обмена сигналами:
    - текст шифруется (encryptMessage),  
    - упаковывается как `{ box, nonce, pubkey }` и отправляется по WebRTC,  
    - другая сторона расшифровывает (decryptMessage) и показывает как `[Remote] ...`.

### Сценарий использования (два клиента)

1. Запустить приложение на **двух устройствах/экземплярах**.  
2. На стороне A (инициатор):  
   - оставить чекбокс «Я инициатор соединения» включённым;  
   - нажать «Старт», скопировать `SIGNAL` или показать QR.  
3. На стороне B (приёмник):  
   - снять чекбокс;  
   - нажать «Старт»;  
   - вставить `SIGNAL` от A в «Вставьте remote SIGNAL» и нажать «Подключить»;  
   - отправить свой `SIGNAL` обратно A.  
4. На стороне A:  
   - вставить `SIGNAL` от B и нажать «Подключить».  
5. После этого поле ввода станет активным — можно обмениваться шифрованными P2P-сообщениями.
